# Project 04 — Labeling Pitfalls: auditing the AFML pipeline

**Status: complete** — notebooks 01–05.

A measurement project, not a tutorial. It takes the labeling pipeline of *Advances in Financial
Machine Learning* (Ch. 3–8) and asks, experiment by experiment, **whether its claims hold and by
how much** — labeling, overlap, cross-validation, meta-labeling, and finally what the pipeline's
own accumulated choices are worth when there is nothing to find.

## Ground rules

1. **Simulated data only**, generated by `src/synth.py`. No market data anywhere in the project.
   The reason is ground truth: the signal is planted, so "did the pipeline recover it?" and — more
   importantly — "did it invent one that was not there?" are both answerable.
2. **Everything from scratch** — numpy, pandas, scikit-learn, matplotlib, scipy. No `mlfinlab`.
3. **No number from a single run.** Any figure quoted in a conclusion is a mean over >= 30 seeds
   with a confidence interval (`src/experiments.py` enforces the shape).
4. **Negative results are results.** Where an experiment fails to confirm the book — or fails to
   confirm the author's own prediction — that is what gets written down.

Each notebook records a **prediction before it is executed** and closes by comparing it against
what came out, plus an explicit "what was not demonstrated" section.

## Notebooks

| # | Notebook | Question | Key finding |
|---|---|---|---|
| 01 | [`01_synthetic_generator`](notebooks/01_synthetic_generator.ipynb) | Is the simulated world defensible, and what exactly is the null? | Reproduces the stylised facts (excess kurtosis **3.68**, ACF(r²) **0.21** at lag 1 vs a ±0.051 white-noise band, ACF(r) ≈ 0) at matched unconditional vol. **`snr=0` is not a null**: with episodes on, `mom_5` still predicts `fwd5` at IC **+0.034** (p=0.003) — a genuine null needs the episodes off |
| 02 | [`02_labeling_fixed_vs_triple_barrier`](notebooks/02_labeling_fixed_vs_triple_barrier.ipynb) | How much does the triple barrier actually change, and what does close-only detection cost? | TB vs fixed horizon differ on **26.1%** of events, almost all of it rescuing the `0` class (sign flips are only 2.2%). Close-only detection mislabels **8.4%** at 1σ barriers, **15.8%** at narrow ones — and with a tight stop the bias goes **one-way** (−6.9 pp of stops missed). **OHLC detection fixes essentially all of it (0.00%)** |
| 03 | [`03_overlap_uniqueness`](notebooks/03_overlap_uniqueness.ipynb) | How much information is really in an overlapping sample, and does sampling density change it? | Average uniqueness **0.073** — governed by *realised* bet duration (14.2 bars), not the vertical barrier. **Effective sample size is ~100 in every dense scheme** (T/duration), so 20× the rows buy nothing; CUSUM at 2σ gets **95% of the information with 19% of the rows**, while fully disjoint sampling *loses* a third of it. One shock contaminates **10.6** labels at 1 obs/bar — a count that scales with density while the *fraction* stays flat at 0.75% |
| 04 | [`04_cv_leakage`](notebooks/04_cv_leakage.ipynb) | Does random k-fold invent skill where none exists? | **Yes — AUC 0.732** [0.721, 0.744] on data where the label is a coin flip (+23 points, p≈4e-27). Purging restores 0.491, but so does *simply not shuffling* (contiguous folds: 0.492) — the embargo adds nothing (p=0.56) and uniqueness weights remove 0.7 of the 23 points. The leak needs **persistent features** (price features 0.763 → AR(1) 0.515 → iid 0.493) and scales with model flexibility (RF 0.732 vs logit 0.588) |
| 05 | [`05_metalabeling`](notebooks/05_metalabeling.ipynb) | Does meta-labeling do what the book says, and what did all these choices cost? | **The F1 argument does not survive**: the best reachable F1 is **0.017 below** the primary alone (p=6e-7) even though the secondary has real skill (AUC 0.611) — with recall 1 the bar is `2p/(1+p)`, and beating it would need precision **0.896** at half the bets. Per-bet Sharpe says +0.545, Sharpe **through time** says −0.040 (p=0.38): the two rank thresholds independently (Spearman −0.08). But **sizing instead of filtering works** — `max(2p−1,0)` gives **+0.453** [+0.310, +0.596] with no threshold to pick. And the bill for the pipeline's own choices: the best of **~186** defensible configurations on **pure noise** shows in-sample Sharpe **1.086**, out-of-sample **−0.103** |

## Code

```
src/synth.py         price generator: GBM + Markov/GARCH vol clustering + planted drift
                     episodes + noisy observable feature + 1-minute intra-bar path
src/labeling.py      fixed-horizon and triple-barrier labeling; three touch-detection modes
                     (close / OHLC / true path) so approximations can be scored against truth
src/uniqueness.py    concurrency, average uniqueness, uniqueness / return-attribution weights
src/cv.py            random, contiguous, purged, purged+embargo k-fold and gapped walk-forward,
                     plus split diagnostics that count train/test window overlaps
src/metalabel.py     primary models (rule / tunable-quality oracle), meta-labels, sided triple
                     barrier, classification vs economic metrics, position through calendar time
src/experiments.py   multi-seed harness: mean_ci, over_seeds, summarise, paired tests,
                     expected-max-Sharpe and the deflated Sharpe ratio
notebooks/_build_NN.py  reproducible notebook builders (nbformat), then `nbconvert --execute`
```

## Reproduce

```bash
uv sync
uv run python projects/04_labeling_pitfalls/notebooks/_build_01.py
cd projects/04_labeling_pitfalls/notebooks
uv run jupyter nbconvert --to notebook --execute --inplace 01_synthetic_generator.ipynb
```

Notebook 01 executes in ~15 s, notebook 02 in ~55 s, notebook 05 in ~6 min (it is the heavy one —
the degrees-of-freedom grid alone fits ~186 configurations x 30 seeds). No network access is
needed at any point.

## What this project does not cover

The obvious next step — contrasting all of the above with the cross-sectional / WorldQuant-BRAIN
frame, where there is no labeling at all and breadth replaces path dependence — is **not** in
here. It needs a multi-asset generator and a different set of claims to test, so it belongs in its
own project rather than as a sixth notebook.
